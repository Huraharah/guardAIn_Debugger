# LLM Integration Implementation Summary

## Overview

This document summarizes the LLM integration that automatically generates GDB debug plans from static analysis artifacts.

## What Was Implemented

### 1. LlmInterface Class (`LlmInterface.h` / `LlmInterface.cpp`)

A comprehensive C++ class that:
- **Collects static analysis artifacts** from the artifacts directory:
  - objdump output (disassembly)
  - strings output
  - readelf output
  - file information
  - SHA256 hash
  - baseline diff (optional)

- **Builds a prompt** that formats all artifacts into a structured request for the LLM

- **Invokes the LLM** via a Python script to generate the debug plan JSON

- **Handles errors** gracefully with detailed error messages

### 2. Python LLM Script (`scripts/generate_plan.py`)

A Python script that:
- Reads the prompt file generated by the C++ code
- Calls the OpenAI API (which Cursor uses internally) to generate the plan
- Extracts and validates JSON from the LLM response
- Saves the plan.json file

**Configuration:**
- Uses `OPENAI_API_KEY` environment variable
- Can be extended to support other LLM providers
- Includes error handling and validation

### 3. RuntimeManager Integration

The `RuntimeManager::analyzeSample()` workflow now:
1. Runs static analysis (objdump, strings, readelf, etc.)
2. Runs dynamic tracing (strace, ltrace)
3. **NEW**: Generates LLM debug plan from static artifacts
4. Runs debug pass using the LLM-generated plan
5. Collects summary

### 4. Documentation

- `scripts/README_LLM_SETUP.md`: Comprehensive setup guide
- This summary document

## How It Works

### Workflow

1. **Static Analysis Phase**
   - `RuntimeManager::runBaselineDiffPass()` runs objdump, strings, readelf
   - Artifacts are saved to `artifacts/<sample_name>/static/`

2. **LLM Plan Generation** (NEW)
   - `LlmInterface::generateDebugPlan()` is called
   - Collects artifacts from the static directory
   - Builds a comprehensive prompt
   - Saves prompt to `artifacts/<sample_name>/LLM/prompt.txt`
   - Calls Python script to invoke LLM
   - Saves plan to `artifacts/<sample_name>/LLM/plan.json`

3. **GDB Script Generation**
   - `GdbScriptBuilder::writeScriptToFile()` reads plan.json
   - Converts JSON plan to GDB script
   - Saves to `artifacts/<sample_name>/debug/plan.gdb`

4. **Debug Execution**
   - `RuntimeManager::runDebugPass()` runs GDB with the script
   - Executes in QEMU VM snapshot
   - Collects debug artifacts

### Key Features

- **Automatic breakpoint detection**: Identifies syscalls, anti-debugging, encryption, etc.
- **Action generation**: Creates appropriate actions (register changes, snapshots, file captures)
- **Anti-debugging bypasses**: Automatically sets registers to bypass common checks
- **File capture**: Handles memfd and other file operations
- **Error handling**: Comprehensive error messages and fallback behavior

## Setup Requirements

1. **Python 3.x** installed and in PATH
2. **OpenAI Python library**: `pip install openai`
3. **OpenAI API key**: Set `OPENAI_API_KEY` environment variable

See `scripts/README_LLM_SETUP.md` for detailed setup instructions.

## Configuration

### Changing the LLM Model

Edit `scripts/generate_plan.py`:
```python
model="gpt-4o"  # Change to your preferred model
```

### Customizing the Prompt

Edit `LlmInterface::buildPrompt()` in `LlmInterface.cpp` to:
- Add/remove artifacts
- Change formatting
- Modify instructions to the LLM

### Adjusting Content Limits

Artifacts are truncated to prevent exceeding token limits:
- objdump: 5000 lines
- readelf: 3000 lines
- manifest diff: 500 lines
- strings: 2000 lines (limited during generation)

Modify truncation in `LlmInterface::collectStaticArtifacts()`.

## Troubleshooting

### Common Issues

1. **Python script not found**
   - Ensure script is at `guardAInDBG/Code/Runtime/scripts/generate_plan.py`
   - Check path resolution in `LlmInterface::invokeLlmForPlan()`

2. **API key not set**
   - Verify: `echo $OPENAI_API_KEY` (Linux/Mac) or `echo %OPENAI_API_KEY%` (Windows)
   - Set the environment variable before running

3. **Invalid JSON generated**
   - LLM may add markdown formatting
   - Script attempts extraction, but manual correction may be needed
   - Check `prompt.txt` for formatting issues

4. **Static artifacts missing**
   - Verify static analysis completed successfully
   - Check `artifacts/<sample_name>/static/` directory

The LLM integration fits into the existing architecture:

```
RuntimeManager
    ├── runBaselineDiffPass() → static artifacts
    ├── runStracePass() → dynamic traces
    ├── LlmInterface::generateDebugPlan() → plan.json [NEW]
    ├── runDebugPass() → uses plan.json
    └── TraceCollector::buildSummary() → final summary
```

## Testing

To test the integration:

1. Ensure all prerequisites are installed
2. Set `OPENAI_API_KEY` environment variable
3. Run the analysis: `guardAInDBG.exe`
4. Check logs for LLM integration messages
5. Verify `artifacts/<sample_name>/LLM/plan.json` exists
6. Inspect the generated plan for correctness

## Notes

- The system continues execution even if LLM generation fails (with warnings)
- The prompt includes comprehensive context from all static artifacts
- The LLM is instructed to generate breakpoints for:
  - System calls (execve, ptrace, memfd_create, etc.)
  - Anti-debugging checks
  - Encryption/decryption routines
  - File operations
  - Library calls (dlopen, dlsym)
